02

The levels: from program to transistor

A computer is understood in levels. Each level uses parts from the level below without caring how they are made: the CPU uses adders, the adder uses gates and the gate uses transistors. The model has every level and you can go down from one to the next with a double-click.

  • Programcontents of the FLASH ROM

    Your code in C, Arduino or ESP-IDF style, translated by the compiler into 16- and 32-bit RISC-V instructions. It's the .hex file.

  • BoardPlacaDevKit

    The crystal (XTAL clock), the RESET and BOOT buttons, an LED on every GPIO, the terminal with its keyboard, the I2C memory and the 74HC595 shift register.

  • ChipESP32C3 · U1

    The CPU, the system bus, the boot ROM, FLASH, SRAM and the peripherals (GPIO, UART, timers, PWM, SPI, I2C).

  • CPUCPU_RV32IMC

    The program counter, the instruction register, the decoder, the 32 registers, the ALU and the control registers.

  • BlocksSumador32, BancoRegistros…

    Adders, multiplexers, decoders, FIFO queues: parts built from gates and flip-flops.

  • GatesSumadorCompleto

    AND, OR, XOR and NOT. A flip-flop stores 1 bit; a 32-bit register is 32 flip-flops sharing a clock.

  • TransistorsLaboratorioTransistores

    CMOS gates built from P and N transistors, a 28-transistor adder, flip-flops and a counter.

So that simulation doesn't take forever, the model uses some components that ship with Logisim (registers, memories, the multiplier) instead of building them gate by gate. The ALU adder is built by hand from gates, and in the other file from transistors, because every addition the CPU makes goes through it.

03

The clock and the CPU phases

PlacaDevKit › XTAL · BUSCANDO (fetching) / EJECUTANDO (executing) LEDs on the panel

The board's XTAL component is the crystal: a signal that rises and falls nonstop. The whole chip is ordered by it following one rule:

  • On the rising edge (when the clock goes from 0 to 1), every register copies what is at its input. It's the only moment anything is stored.
  • Between one edge and the next, combinational logic (gates, adders, multiplexers) computes the new values from what is stored. Signals travel through the gates one after another until they settle.

In a real chip that trip takes a few nanoseconds and sets the maximum frequency: the longest path, the critical path, has to finish before the next edge. In Logisim, every time the clock changes the simulator propagates signals until they settle. If you disable simulation with Ctrl+E, you can watch that propagation step by step with Ctrl+I.

The model's CPU is multicycle: it runs each instruction in phases, one per clock cycle.

PhasePanel LEDWhat happens
BUSCA (fetch)BUSCANDOThe PC goes out on the bus and memory answers with the instruction. On the edge, the IR stores it.
EJECUTA (execute)EJECUTANDODecodes, reads the registers, computes in the ALU or uses the bus to read or write data. On the edge it stores the result and updates the PC.
BUSCA2 (fetch 2)BUSCANDOOnly sometimes: when a 32-bit instruction is split across two memory words, a second read is needed.

That's why the panel shows a little more than twice as many cycles as instructions: about 2.2 cycles per instruction.

04

Inside the CPU

PlacaDevKit › U1 › CPU (CPU_RV32IMC)

The CPU executes the RISC-V RV32IMC instruction set, the same as the real ESP32-C3. RV32I is about forty basic 32-bit instructions: add, compare, branch, load and store. M adds multiply and divide. C adds 16-bit compressed versions of the most common instructions, so programs take less space.

It has 32 registers of 32 bits, x0 to x31. x0 is always 0. The others are named after how the compiler uses them: ra holds the return address, sp points to the stack, a0–a7 carry function arguments and results, t0–t6 are temporaries and s0–s11 are preserved across calls. In the State tab you see them as x01_ra, x02_sp, etc.

It's a load/store architecture: the ALU only works on registers. To use a value from memory you first load it with lw, and to store it, sw.

05

Every addition: the ALU and the adder

U1 › CPU › U_ALU › SUMADOR (adder) › FA0 … FA31

Almost everything the CPU does ends in an addition: add and addi, but also sub (A + not B + 1), the slt comparisons (subtract and look at the sign) and the computation of every address. The ALU has a 32-bit adder made of 32 full adders in a row.

A full adder adds three bits (a, b and the incoming carry) and outputs the sum and the outgoing carry:

s = a ⊕ b ⊕ cin
cout = a·b + cin·(a ⊕ b)

Each bit's carry is the next one's input, so in the worst case the signal crosses all 32 adders one after another. This is a ripple-carry adder: simple but slow, and often the critical path of a simple CPU. Fast processors use carry-lookahead adders, which compute the carries in parallel.

Watch it

Stop the clock (Ctrl+K), disable simulation (Ctrl+E) and in the Simulate tab go into PlacaDevKit › U1 › CPU › U_ALU › SUMADOR. Press Ctrl+T and then Ctrl+I several times: you'll see the values arrive and the carry move from FA0 towards FA31. When you're done, enable simulation again with Ctrl+E.

In ESP32C3_Logisim_ALU_transistores.circ each FA is a 28-transistor SumadorCompletoCMOS: you can go one level deeper.

The CPU's other adders (PC + 4, the branch target and the address adder) use Logisim's built-in adder, so the simulation runs faster.

Reading instructions

debug panel › row instrucción (IR)

Every 32-bit RISC-V instruction is split into fields. The low 7 bits (the opcode) say what kind of instruction it is, and depending on the kind the rest is shared between registers (rd, rs1, rs2), variants (funct3, funct7) and the immediate. Registers are always in the same place: that's why the register file can start reading before the decoder finishes.

The bus and the memory map

U1 › BUS (BusSistema) · LECTURA (MuxLectura, read mux) · APB

The CPU has a single bus. In the fetch phase it uses it to read instructions and in execute to read or write data. Each 32-bit address points somewhere different: the address decoder looks at the high bits and raises a single sel_… signal; the read multiplexer lets only the selected device's data through to the CPU.

Peripherals are memory-mapped: a peripheral register is read and written with lw and sw, just like RAM. The difference is that writing there does something: turn on a pin, send a character, start a timer.

If the CPU asks for an address where nothing lives, writes to FLASH or tries to execute from a place that isn't code, the bus answers with an error and the CPU jumps to the exception handler. The terminal shows a Guru Meditation Error and mcause says what happened (for example, 7 = store not allowed).

The model's memories answer in the same cycle, which is why an lw finishes inside the execute phase. In the real chip the flash is outside the processor, connected over SPI, and read through a cache.

A signal's journey to the GPIO

U1 › GPIO (GPIO_IOMUX) › PAD8 (PadGPIO)

What happens between digitalWrite(8, HIGH) and the red LED lighting up? Let's follow the signal.

  • sw a1, 8(a0)instruction
  • CPUexecute
  • bus0x60004008
  • sel_GPIOdecoder
  • GPIO_OUTregister
  • matrix and IO MUXwhat goes out on the pin?
  • PAD8output buffer
  • LEDboard

  1. The program

    digitalWrite(8, HIGH) calls gpio_set(8, 1), which writes 1 << 8 to the GPIO_OUT_W1TS register (address 0x60004008). The compiler turns it into an instruction like sw a1, 8(a0), with a0 = 0x60004000 and a1 = 0x100.

  2. Fetch

    The CPU brings that instruction in from FLASH.

    Panelbus: lee (read) = 1, dato leído (data read) = 00b52423

  3. Execute

    The address adder computes a0 + 8 = 0x60004008. The CPU puts that address and the data 0x100 on the bus with the write signal at 1.

    Panelbus: address 60004008 · escribe (write) = 1 (LED BUS_ESCRIBE) · data written 100

  4. Address decoder

    The address starts with 0x600, so it's a peripheral; page 0x60004 is the GPIO. sel_GPIO goes high and only that block sees the write.

    LogisimU1 › BUS: sel_PERIFERICOS, sel_GPIO

  5. The GPIO_OUT register

    On the rising edge that ends the execute phase, the register stores OUT | 0x100. W1TS means "write 1 to set": bits at 1 turn on and the others don't change. Its partner W1TC (0x6000400C) turns off.

  6. GPIO matrix and IO MUX

    Each pin can output a peripheral's signal (UART, LEDC, SPI…) or the GPIO_OUT bit. For pin 8, GPIO_FUNC8_OUT_SEL = 128 means "plain GPIO", and the IO MUX is set to function 1 (GPIO). Bit 8 of GPIO_ENABLE enables the output; pinMode(8, OUTPUT) set it to 1.

  7. The pad

    PAD8 drives the pin with a tri-state buffer: if the output is enabled it puts the value on the line, and if not it leaves it free to be used as an input, with pull-up or pull-down.

    LogisimU1 › GPIO › PAD8: valor_salida, oe_final

  8. The board

    The pin's line reaches the red LED, which lights up. It all happens on the same edge: from the register to the LED there are only gates, no other flip-flop in the way.

And the other way: a button coming in

When you press BOOT, pin GPIO9 drops to 0. The pad passes it inward (if the input is enabled) and two flip-flops in a row, SINC1 and SINC2, synchronize it to the clock, as in the real chip, so a half-changed value is never read. Out of that comes GPIO_IN (0x6000403C), which the program reads with lw. That's why the button takes two cycles to "arrive". A third register, ANTERIOR (previous), keeps last cycle's value to detect edges: that feeds the interrupts.

09

Interrupts

U1 › INTERRUPT (MatrizInterrupciones) · CPU › CSR

A program can wait for a button by reading GPIO_IN over and over, but it's more efficient for the hardware to give notice. That's an interrupt: the CPU drops what it was doing, runs a function that handles the notice (the interrupt service routine, or ISR) and returns exactly where it was, without the main program noticing.

  1. The GPIO detects the edge

    With attachInterrupt(9, …, FALLING) pin 9 is configured for falling edge. When SINC2 is 0 and ANTERIOR is 1, bit 9 of GPIO_STATUS turns on.

  2. The interrupt matrix picks a line

    The ESP32-C3 has 62 interrupt sources and the CPU has 31 lines. The matrix connects each source to a line with a priority: the SDK connects source 16 (GPIO) to line 31 with priority 3. A tree of comparators (NodoPrioridad) picks the pending line with the highest priority.

  3. The CPU takes the interrupt

    At the start of a fetch phase, if an interrupt is pending and mstatus.MIE = 1, the CPU doesn't fetch the instruction: it saves the PC in mepc, the cause in mcause (0x8000001F: interrupt on line 31), clears MIE so it isn't interrupted again and jumps to mtvec + 4 × 31.

    Statemepc, mcause, mstatus_MIE

  4. The vector table

    At that address there's a jump to _irq_entry, which saves 16 registers on the stack (sixteen sw in a row you'll see on the panel) and calls the SDK dispatcher. It reads GPIO_STATUS, clears it by writing GPIO_STATUS_W1TC and calls your function.

  5. Returning

    The registers are restored and the mret instruction returns the PC to mepc and turns MIE back on. The main program carries on as if nothing happened.

Exceptions use the same mechanism: an illegal instruction, an invalid address or an ecall also save mepc and mcause and jump to mtvec, but to entry 0 of the table.

Compiling on Windows

  1. Open ESP-IDF CMD or ESP-IDF PowerShell (the shortcuts left by the ESP-IDF installer). That way the riscv32-esp-elf-gcc compiler and Python are already available. A normal terminal works too if you have Python: the script looks for the compiler in %USERPROFILE%\.espressif. On macOS and Linux it works the same way.
  2. Go into the sdk folder and compile an example:
cd path/to/esp32c3-logisim/sdk
python compilar.py arduino/blink
  1. Open arduino/blink/logisim/blink.circ: it's a copy of the circuit with the program already loaded. Press Ctrl+K.

To load a .hex into the circuit you already have open: double-click ESP32C3 in the Design tab, right-click the FLASH ROM › Load Image…, pick the file, go back to PlacaDevKit and press RESET.

Your own program

Copy an example folder (for example arduino/blink to arduino/my_program), rename the .ino so it matches the folder, edit it and compile it:

python compilar.py arduino/my_program
python compilar.py idf/my_app            # ESP-IDF: a folder with main.c and app_main()
python compilar.py examples/my_test      # C with main() and sdk.h

The script detects the style by itself: setup() and loop() is Arduino, app_main() is ESP-IDF and main() is C. Useful options: --ciclos-por-ms 4 makes each millisecond of the program last 4 cycles instead of 1 (useful if your program does a lot of work between short pauses; pauses get longer), --cc PATH sets the compiler and -v shows the commands.

What happens when you press RESET

  1. The boot ROM

    The PC starts at 0x40000000. The ROM prints ESP-ROM:esp32c3-logisim and the reset reason, and reads the strapping pins: if BOOT (GPIO9) is held, it enters download mode and waits, like the real chip.

  2. The FLASH marker

    If the first 8 bytes of FLASH are 0xAEDB041D 0xAEDB041D (the ESP32-C3 "direct boot"), it jumps to 0x42000008.

  3. start.S

    Sets up gp and sp (the stack starts at the end of SRAM), copies initialized variables (.data) to SRAM, zeroes the rest (.bss), points mtvec to the vector table and calls sdk_init, the C++ constructors and main().

  4. Your code

    In C, main() is yours. In Arduino, main() calls setup() once and loop() forever. In ESP-IDF, it creates the main task and calls app_main().

What's different

  • Time runs in slow motion. 1 ms of the program = 1 cycle of the model, so delay(1000) is 1000 cycles: a few seconds in Logisim, depending on your computer.
  • FreeRTOS is cooperative. Tasks switch only when one calls vTaskDelay, waits on a queue or semaphore, or calls taskYIELD(). A task with an infinite loop and no pauses doesn't let the others run. On the real chip the scheduler preempts tasks every millisecond.
  • No Wi-Fi, Bluetooth or ADC. They are radio and analog circuits Logisim doesn't simulate; analogRead() returns 0.
  • The UART has a fixed speed. Serial.begin() accepts any value, and each character takes 40 cycles to go out.
  • PWM is 8 bits in hardware. If you ask for more resolution (for example 13 bits in ESP-IDF), the value is scaled.
  • Source code is compiled. A binary built with idf.py build or the Arduino IDE won't run on the model: it uses another image format and other libraries.

The transistor lab

Design tab › double-click LaboratorioTransistores

A MOS transistor is a switch controlled by a voltage. The N type conducts when its gate is 1 and is good at passing a 0. The P type conducts when its gate is 0 and is good at passing a 1. In a CMOS gate there is always a network of P transistors connecting the output to 1 and an N network connecting it to 0, and both never conduct at the same time.

In the labTransistorsHow it's built
Inverter (NOT)2A P on top and an N below, with their gates tied together.
NAND4Two P in parallel on top and two N in series below. NOR is the other way around.
Full adder28The "mirror" adder: one stage computes the inverted carry and another the sum, without going through separate gates.
4-bit adder112Four 28-transistor adders in a chain, with displays to see the numbers.
D latch, D flip-flop and counter—Transistor NANDs with feedback. The master-slave flip-flop copies on the rising edge; the counter uses four flip-flops and the transistor adder, with its own clock (Ctrl+K).

In Logisim, if a transistor's gate has no defined value, the output is undefined (blue) or in error (red). A freshly powered latch doesn't know which value to hold, so the ones in the lab have a reset input that puts them in a known state.

To go back to the board: double-click PlacaDevKit in the Design tab.

Experiments to try

  • Count an instruction's cycles

    Stop the clock with Ctrl+K and step with Ctrl+T. Watch BUSCANDO and EJECUTANDO alternate and the PC change every two cycles, sometimes three.

    any program

  • Catch an addition

    Step until the panel's operation is 0 and check in hex that A + B = result. Then look for a subtraction (8) and a comparison (2 or 3).

    hola_mundo (computes 123456 × 789)

  • Follow the write to the LED

    Open Simulate › Timing Diagram and add XTAL, BUS_ESCRIBE and the red LED. You'll see the LED change on the same edge that ends an sw to 0x60004008 or 0x6000400C.

    parpadeo, arduino/blink

  • Watch the carry travel

    With simulation disabled (Ctrl+E), go into SUMADOR through the Simulate tab, press Ctrl+T and step with Ctrl+I.

    any program

  • Live interrupt

    Press BOOT while it runs and watch mepc, mcause and mstatus_MIE change in State. The PC jumps to the vector table (0x420001xx).

    arduino/boton_interrupcion, interrupciones

  • Task switch

    Each FreeRTOS task has its own stack. Watch x02_sp in State: it jumps from one SRAM region to another every time the scheduler switches tasks.

    idf/tareas_y_colas

  • Change a program

    Edit sdk/arduino/blink/blink.ino: change the pin or the delay, compile with compilar.py and open the .circ it generates.

    arduino/blink

  • Cause an exception

    Write to FLASH: *(volatile int *)0x42000000 = 1;. The terminal shows the Guru Meditation Error with mcause = 7, and mepc points to the guilty instruction.

    examples/hola_mundo modified

How it compares to the real chip

The model follows the ESP32-C3 technical reference manual: same addresses, same registers and same instruction set. What changes is whatever would make simulation impossible or endless.
